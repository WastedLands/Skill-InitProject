# Design: {{PROJECT_NAME}}

The single design doc for planning-lite projects. Authoritative for scope, contracts, semantics, limits, and acceptance criteria. Keep it current — it rots the moment it disagrees with the code. For larger projects this role is played by `openspec/specs/` instead.

## Product scope

{{SCOPE}} — what the product does and does not do. Non-goals from `docs/NORTH-STAR.md` apply.

## Contracts

{{CONTRACTS}} — the interfaces that matter: tool/API contracts, input/output shapes, error codes. Define them before implementing.

## Semantics and limits

{{SEMANTICS}} — how results are shaped, what empty/partial results mean, budgets, timeouts, caching rules.

## Acceptance criteria

{{ACCEPTANCE_CRITERIA}} — the checks that must pass before a slice is considered done. Link each to the test or verification that proves it (or mark `none yet`).

## Open questions

{{OPEN_QUESTIONS}} — decisions not yet made. Resolve them before they block a slice; record the resolution in `docs/decisions/`.
